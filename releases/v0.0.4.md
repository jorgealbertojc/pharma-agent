# 0.0.4 - Core module completion: data models and exception hierarchy

This release finalizes the core module by adding centralized data models and a complete exception hierarchy, providing a solid foundation for the API and CLI entrypoints.

## Added

### Core Data Models (`src/core/models.py`)

- **QueryRequest**: Pydantic model for user questions with optional `session_id` for conversation memory.
- **AgentResponse**: Structured response model with `answer`, optional `sources`, `suggestions`, `inventory_results`, and `error` fields.
- **ErrorResponse**: Standardized error format for API responses.
- **Field validator** for `question` to strip whitespace and reject empty/blank inputs.

### Custom Exceptions (`src/core/exceptions.py`)

- **AppException**: Base exception with `message` and optional `details` for all application errors.
- **ConfigurationError**: For missing environment variables or invalid credentials.
- **ServiceConnectionError** and subclasses for external services:
  - `PineconeError`
  - `RedisError`
  - `GoogleSheetsError`
  - `OllamaError`
- **DataValidationError**: For invalid input data (Pydantic or business logic).
- **RAGError** with `DocumentNotFoundError` and `IndexingError`.
- **InventoryError** with `ProductNotFoundError`.
- **AgentError** with `ResponseGenerationError` and `MemoryError`.
- **NotFoundError**: Generic resource not found.

### Tests

- Comprehensive unit tests for all models (valid input, optional fields, whitespace trimming, error handling).
- Full test coverage for exception hierarchy (inheritance and string representation).
